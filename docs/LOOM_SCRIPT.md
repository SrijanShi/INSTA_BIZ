## 8:00 Decisions and challenges (2 min)

**Screen:** `src/components/mascot/rig.ts`, then `PupJourney.tsx`, then `src/styles/components.css` (the button fix).

- Teddy is code, not an image: `fluff()` draws the wobbly fur, poses are numbers, `frame()` turns pose + motion into transforms, `PupDriver` animates it every frame. `PupJourney` moves one Teddy between the scenes as you scroll.
- Static by default; the puppy filters render on the client behind a Suspense fallback (a Next 16 Cache Components rule).
- Media self-hosted so the clone doesn't depend on the original server; JPEGs optimised.
- Forms log enquiries unless Resend is configured, so the real business never gets test emails.
- Challenges: Next 16 differences (read the bundled docs first), very large tool outputs, a CSS formatter bug caught by the build, data quirks in gone-home pages, and the flickering hover button that the mobile tests found (the original has it too).

### Likely questions

- *How does the puppy filter keep state?* In the URL. `PuppyBrowser` reads `useSearchParams` and writes with `history.replaceState`, which Next.js syncs without a server round trip.
- *Where does the data come from?* `src/content/*.json`, generated by `scripts/extract-content.mjs` from the original pages' RSC payloads. `src/lib/content.ts` types it.
- *How do the forms work?* `src/app/actions/enquiry.ts` is a Server Action. `useEnquiry` wraps `useActionState`. Validation is server-side; errors come back per field.
- *Why is the walker home-only?* That's how the original works: its CSS hides the static Teddies only while the walker runs.
- *Accessibility?* Skip link, labelled controls, dialogs for menu and viewers, `aria-pressed` on filter chips, tabs with arrow keys, reduced motion respected everywhere.
